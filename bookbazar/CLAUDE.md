# CLAUDE.md

Guidance for Claude Code (and humans) working in this repo. See `README.md` for the full feature list, API map and data model.

## Hard rules

- **Never `git commit` or `git push`.** Leave changes in the working tree and tell the user what changed. They commit.
- **Never touch `main`** and never check out, rebase, merge into or push to a branch another person is working on. Work only on the branch that's already checked out.
- **Every feature or change ships with tests.** Add or update a file under `tests/`, run it locally against the Docker test stack (`npm run test:docker`), and report the real pass/fail output.
- **Never point anything at the real `.env` database or Redis** for testing or destructive commands. Tests use `docker-compose.test.yml` only, and `tests/setup/local-url.ts` enforces that.
- Don't hand-edit `lib/generated/prisma/*`. It's generated by `prisma generate`.

## Layout

- The git root is the **parent** folder (`bookbazaar/`). The Next.js app is `bookbazar/`. Run every npm/npx command from `bookbazar/`.
- `app/api/**/route.ts`: REST handlers. `app/lib/`: session JWT, `requireActiveUser`, `requireAdmin`. `lib/`: domain logic (credits, coupons, seller payouts, fuzzy search, slugs, recommendations, Resend emails). `prisma/schema.prisma` is the data-model source of truth.

## Commands

```bash
npm run dev               # dev server
npm run lint              # eslint
npm run test:unit         # fast, no Docker
npm run test:docker       # start Postgres+Redis containers, run all tests
npm run test:e2e          # Playwright browser tests (UI/layout changes need one in tests/e2e/)
npm run test:db:down      # stop/wipe test containers
npx vitest run --project integration <file-substring>   # one integration file
```

Type-check with `npx tsc --noEmit`. If it fails inside `.next/dev/types/validator.ts`, the `.next` folder is stale; that isn't a real error.

## Conventions to follow

- **Auth in route handlers:** use `requireActiveUser()` for user endpoints (it also rejects blocked users) and `requireAdmin()` from `app/lib/require-admin.ts` for admin endpoints. Don't copy-paste a local `requireAdmin`.
- **Validation:** a zod schema + `safeParse`, then `Response.json({ message }, { status: 400 })` on failure. Responses are `Response.json({ message, ...data }, { status })`.
- **Dynamic params** are async in Next 16: `context: { params: Promise<{ id: string }> }` → `const { id } = await context.params`.
- **Money:** only change `User.creditBalance` through `applyCreditTransaction` (`lib/credits.ts`), inside a transaction. Redeem coupons only through `redeemCoupon`. Anything that reduces what the buyer pays must also call `allocatePayoutAdjustments` so the seller is owed the difference. Guard stock and balances with conditional `updateMany`, never read-then-write.
- **Either/or relations** (school `classSubjectId` vs university `programSubjectId`): enforce "exactly one" in zod, and check for duplicates by hand, because Postgres doesn't de-dupe NULLs in unique keys.
- **Slugs:** use `generateUniqueSlug` / `generateUniqueStoreSlug` / `generateUniqueStudyMaterialSlug` from `lib/slug.ts`.
- **Soft delete** books (`isActive: false`). Public queries must filter `isActive: true` and `store: { isActive: true, isApproved: true }`.
- **Email** failures after a saved decision are caught and logged, not returned as errors.
- Match the surrounding style. Files vary: newer code is clean with no semicolons; some older files are loosely formatted. Don't reformat files you aren't otherwise changing.

## Writing tests

- `tests/unit/*.test.ts`: pure logic, no DB.
- `tests/integration/*.test.ts`: call the exported route handler directly:
  ```ts
  beforeEach(resetDb)
  const user = await createUser()            // tests/helpers/db.ts factories
  await loginAs(user)                        // tests/helpers/auth.ts — sets the mocked session cookie
  const res = await POST(jsonReq("/api/x", body))          // tests/helpers/http.ts
  const res2 = await PATCH(jsonReq("/x", body, "PATCH"), params({ id }))
  ```
- Resend, Cloudinary and `next/headers` are mocked globally (`tests/setup/mocks.ts`). Check emails with `vi.mocked(resend.emails.send)`. Mock `fetch` with `vi.spyOn(globalThis, "fetch")` for OAuth-style external calls.
- Integration files run one after another against a shared, per-run database. Always `resetDb` in `beforeEach`.

## Known traps

- **Migrations are baselined.** `prisma/migrations/0_init` is the full schema as of 2026-10-27; `prisma/migrations-archive/` holds the old, incomplete history and is never used. Schema changes go: edit `schema.prisma` → `npx prisma migrate dev --name x` (local dev DB only) → commit the new folder. Never use `db push`, and never edit `0_init` or other applied migrations. `tests/integration/schema-drift.test.ts` fails if a schema change has no migration.
- Existing databases need `npx prisma migrate resolve --applied 0_init` once (README → Database migrations). That writes to a real database, so the user runs it, not Claude.
- Prisma blocks destructive commands (`db push --force-reset`, `migrate reset`) when run by an AI agent unless the user explicitly consents. Ask; don't work around it.
- `tsx`/`dotenv` for the seed scripts come from the parent folder's `package.json`.
- Host ports 5433/5434 are used by other local projects. The test stack uses 54329 (Postgres) and 63799 (Redis).
